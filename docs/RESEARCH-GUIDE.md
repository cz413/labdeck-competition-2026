# 对照实验与可恢复流程（0.6.0）

本版在独立比赛目录实现了 LangGraph 实验编排、实验运行 Harness 和实际编译的仓颉参数引擎。沿用已有任务调度、SSH、模型设置和故障修复。原项目未修改。

## 快速演示（不需要服务器或模型）

1. 打开「智能实验 → 对照实验」，点击「载入对照演示」。
2. 查看四份配置：两个学习率 × 两个 seed。参数由启动自检通过的仓颉引擎展开，否则明确标记为 TypeScript 回退。
3. 点击「审查并确认本批入队」，确认「模拟入队」。
4. 选择「模拟正常结束（含指标变差）」，查看指标与退出码：指标更差仍归为正常运行结果。
5. 重置后，可选择「模拟一项运行故障」，观察科学结果与运行故障的分离。
6. 退出、切换页面或重载清除模拟状态。演示运行、指标、退出码和流程状态都是预设数据；不调用 SSH、模型或真实任务写入，不保存 LangGraph 检查点。

演示只调用 `research:preview` 的本地参数展开。实际研究记录和演示记录分开，临时记录有「模拟」标记。

## 使用实际任务

1. 添加实际服务器、核对 SSH 主机指纹，准备一个命令模式 Python 任务，例如 `python train.py --lr 0.01 --batch-size 16`。
2. 在任务详情点击「设计对照实验」，或在对照实验页选取来源任务。
3. 描述研究问题，手工填写参数；已配置模型时可点击「AI 设计范围」，审查参数支持性及假设。模型只建议参数范围，不能替换服务器、目录、脚本或直接运行命令。
4. 设置本批运行预算（1～32）；组合超预算会阻止生成。重复候选值会去重。
5. 点击「生成待审查方案」。这一步只保存流程及配置，不创建运行。
6. 查看基准命令、配置变化、产物目录说明，确认本批服务器、环境和全部命令后入队。每个配置建立新任务，并连接现有 GPU 队列；来源任务及运行保持原样。
7. 任务调度器报告状态变化后唤醒流程。等待阶段不轮询大模型；也可点击「检查进度」。
8. 本批全部运行结束（完成、失败或取消）后，读取日志尾部及远程退出码，提取指标。故障分支最多自动诊断四项，复用已有诊断报告；修复仍需单独确认。
9. 查看结果对比及证据。启用模型分析时获得总结与下一批参数建议；「载入下一批建议」只填入新方案，仍须生成、审查并重新确认。
10. JSON 导出包含基准配置、参数、任务/运行编号、证据、结果和节点时间线。

每次结果分析最多补充两次。模型失败或引用不存在的证据时保留结构化观察，并记录原因。模型本身分析是否正确仍需要研究者核对。

## 恢复与边界

- 流程位于 `%APPDATA%/LabDeck-Competition-2026/research/`，采用 LangGraph 检查点、二进制序列化和原子文件替换。
- 重启恢复待确认、等待运行等状态。远程运行状态继续由已有任务调度器核对。
- 批量提交使用研究编号和配置序号作为去重标记，恢复时核对已创建任务与运行。部分入队后继续不会重复启动已提交项。
- 若已生成子任务的配置被改动，停止剩余提交并提示核对；不覆盖人工修改。
- 暂停跟踪不停止已入队的远程实验；取消运行在任务栏处理。
- 任务被删除、服务器连接变化或证据缺失会提示处理，不把缺少证据转换为科学成功。
- 未指定结构化文件时，指标来自末尾 240 行 / 64 KiB 日志并取最后匹配值。指定文件时按 [结构化结果协议](RESULTS-GUIDE.md) 采集，保留数据集、阶段、单位、epoch/step、方向与来源。
- 支持用户指定的 metrics.json 及预期产物元信息；尚不解析 TensorBoard 或 checkpoint 内容。文件缺失、格式错误和归属未知是证据问题，不自动判运行失败。可以在本批结束后重新采集证据，不重启运行。
- 没有强制科学指标阈值。正常退出仅意味着运行结束；假设未成立也是实验观察。
- 不自动修改训练源码、安装依赖或执行自由 Shell。第一版只展开无引号、无空格参数值的简单 Python 命令。
- 子任务继承产物配置，脚本若会覆盖同名文件，需要先确认其独立输出方式。日志由现有调度器按运行编号保存。
- 当前历史辅助只按项目、代码目录匹配近期任务，不宣称已实现代码版本溯源、向量 RAG 或跨项目知识库。

## 仓颉编译与复现

`cangjie/parameter-engine/main.cj` 使用标准库完成：输入校验、参数去重、笛卡尔积展开、运行次数预算、既有参数替换和命令生成。CLI 采用严格 TSV 输入和 JSON 输出，避免为小型确定性引擎增加 stdx 依赖。

已使用官方 Cangjie 1.0.5 Windows x64 SDK 实际编译。下载包 SHA256：`08C6C1DD0DE73396F63AC85085D635E79CE84FEF98D330CB00869B4FC8F1CB2E`。SDK 仅位于本比赛目录的 `artifacts/cangjie-sdk`，没有全局安装或修改系统 PATH。

```powershell
npm run build:cangjie
# 或用已有 SDK 目录：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-cangjie.ps1 -SdkRoot C:\path\to\cangjie
npm test
npm run verify:research
npm run dist:competition
```

编译脚本只在自身进程中配置 SDK 环境。可执行文件、运行时和官方许可文件放在 `resources/cangjie`，打包后位于 `resources/cangjie`，从 ASAR 外调用。SDK 本身不打包。

宿主侧再次校验仓颉输出与协议约定。仓颉可执行文件缺失或启动自检失败时明确标注 TypeScript 引擎和原因；自检通过后的实际请求若执行或协议校验失败，则阻止本次生成。自检状态在当前服务实例内缓存，重新编译后请重启应用。

## 验证事实（历史与当前环境分别记录）

单元/集成测试使用实际仓颉引擎和实际 LangGraph；验证参数展开、预算、配置约束、暂停、磁盘恢复、部分入队去重、指标变差及模型失败降级。

`verify:research` 使用真实 Electron 页面、preload 和 IPC，实际 LangGraph 与仓颉引擎；SSH 和模型回复为测试夹具。它验证导航、确认取消、批量入队、等待期间不调用模型、重启、下一批审查、演示隔离及深浅主题。验证结果在 `artifacts/research-ui-verification.json`。

本机测试不等于真实训练验证；使用者自己的模型服务、GPU 节点和训练脚本还需要实际运行确认。

`npm run verify:research:package` 使用发布版 Electron 检查 ASAR 内的实际 LangGraph 运行、仓颉原生展开及预算限制，并核对构建文件。`@langchain/core` 显式列为运行依赖，保证打包器包含 LangGraph 所需的共享依赖。检查不启动应用调度器，也不连接真实服务器。


0.6.0 本机验证详情见 [VALIDATION.md](VALIDATION.md)：实际 LangGraph、TypeScript 参数回退、结构化指标采集和 Electron 联调通过。仓颉启动自检失败，原生专项跳过并报告原因；严格验证命令 `npm run verify:cangjie` 会报错。当前结果不能作为仓颉运行成功或真实训练效果的证明。
