# 比赛版功能记录

以下是独立比赛版的功能迭代记录。当前仓库从 0.5.0 源码快照开始记录 Git 提交；本文件不是此前 Git 历史的重建。

## 0.6.0

- 修复新版 Windows 下的仓颉初始化访问冲突：将官方 #920 两处变更等价回移到固定 SHA256 的 1.0.5 运行时，保留配套 SDK/ABI；产物明确为本地未签名版本，构建先自检再替换。
- 仓库分析统一最多四次模型请求，不自动重试；侦察失败保留已读内容和原因，支持取消并中止 HTTP/SFTP。
- 文件勾选范围成为实际读取边界；目录/环境名不再误消除数据预处理或依赖版本问题；README 回退按目标筛选唯一命令。
- 构建和 Electron 验证使用项目内临时目录，避免系统 Temp 权限问题，验证启动器清除继承的 Electron Node 模式。


- 仓库路径增加服务器目录浏览器，可从主目录逐级选择并确认仓库根目录。
- 存在明确启动命令但仍有非阻塞待确认项时，可“仍然保存为草稿”，待确认项写入任务备注。
- 预填的数据目录和 Conda 环境自动回答对应的模型问题，不再重复要求填写；准备步骤显示可只读核验的环境/数据提示。
- 仓库路径支持服务器扫描（常见目录下带 `.git` 或 README 的候选）和最近路径候选，减少手填绝对路径。
- 数据目录与权重/检查点目录增加只读存在性核对；Conda 环境名与服务器环境列表比对；保存流程去掉多余确认，直接进入 GPU 选择。
- 仓库启动界面增加只读侦察轨迹、当前阶段提示和最近仓库路径候选；准备事项支持一键全部确认/撤销。
- 仓库启动改为模型只读侦察（`read_file` / `list_dir` / `find_files`）后再生成方案：默认读 README/依赖/入口，最多 3 轮、8 次工具调用；侦察失败保留已读内容继续生成一次方案。
- 修复诊断缓存键未包含日志来源、导致示例与粘贴日志互相复用的问题；示例与粘贴日志每次重新生成报告。修复未显式传入重试选项时未继承原诊断模型分析选择的问题。
- 仓库启动保存后直接打开 GPU 选择并入队，不再要求先去任务池找任务；Conda 环境从服务器读取候选，数据目录从仓库内 `data/`、`checkpoints/` 等目录或 `--data` 参数预填。
- 仓库启动指南优先读取 README/配置引用的脚本，入口已知时给出最小建议启动命令；模型留空时从 README 原文回退，并从 `environment.yml` 的 `name` 与 `--data` 参数预填环境名和数据目录。
- 新增 `LABDECK_DATA_DIR` / `--labdeck-data-dir` 数据目录覆盖；主进程检测到 AppData 不可写时会自动改用仓库内 `.labdeck-data`，并连同 `Local State` 复制现有数据以保持 `safeStorage` 凭据可解密；dev 脚本在 Electron 沙箱初始化失败时自动用 `--noSandbox` 重试一次。
- 修复集成终端继承 `ELECTRON_RUN_AS_NODE=1` 时 `npm run dev` 把 Electron 当成纯 Node 运行、报 `does not provide an export named 'BrowserWindow'` 的问题；新增 `npm run dev:nosandbox` 备用命令。
- 智能实验导航中的“启动实验”更名为“仓库启动”；仓库分析改为模型按需只读侦察可读文本文件，默认单次约 30 万字符（`LABDECK_REPO_MAX_CHARS` 可调），超出部分跳过并提示；取消 6 个文件、64 KiB 单文件和 32 Ki 总字符限制及 8192 tokens 输出上限，仓库请求超时 600 秒。
- 修复 SSH Config 导入时误读 LabDeck 自动生成的 VS Code 配置、导致名称变为 labdeck-xxx 的问题；重新导入时可恢复匹配的原始 Host 名称，保留服务器 ID、连接凭据和历史关联。

- 新增用户指定 metrics.json 和预期产物采集配置，随批次审查、保存和导出；保留来源、数据集、阶段、单位、epoch/step 和优化方向。
- 进程状态、证据完整度和研究观察分开展示；指标未提升不判故障，缺失产物不触发修复。
- 支持只读重新采集，不创建运行、不自动诊断或调用模型；保留现有诊断关联。
- 文件采集使用隔离模式 Python 3、128 KiB 有限读取、文件变化检查和运行归属提示；指标无效时不以日志冒充结果文件。
- 新增参数引擎启动自检、明确的 TypeScript 回退与严格原生验证命令。本机仓颉初始化问题仍有记录，未将跳过测试计作原生验证成功。
## 0.5.0

- 新增任务到对照实验的入口，支持手工或 AI 参数轴、配置差异、组合数及预算审查。
- LangGraph 编排确认、入队、等待、采集、诊断与分析，磁盘检查点支持重启恢复和部分入队去重。
- 实际编译仓颉 1.0.5 参数引擎，负责组合展开、去重、预算与命令生成，运行组件随程序打包。
- 自动提取日志指标，比较配置与证据；指标未提升不判故障，下一批建议仍需确认。
- 对照演示使用实际参数引擎、模拟运行与预设指标，不写入真实任务历史。

## 0.4.0

- 实验任务、指定运行与诊断报告准确联动；支持归档任务定位和报告返回原运行 / 修复运行。
- 基于已有任务生成新计划草稿，审查与排队继续由用户触发。
- 离线演示覆盖计划、OOM、确认修复、模拟成功 / 失败、重置和退出，演示会话只保存在窗口内存。

## 0.3.0

- 确认修复后自动跟踪新运行，结束时读取远程退出码；失败关联下一份诊断。
- 跟踪状态持久化；连接失败、退出码缺失或证据不足时有限退避重查，支持暂停、恢复和手动核验。
- 仅验收进程状态，后续修复仍需再次确认。

## 0.2.0

- 模型按日志选择受限只读工具，最多四轮请求和四项检查，每轮最多两项。
- 支持证据 ID 校验、重复检查去重、过程记录与停止诊断；模型失败保留规则结果和已有证据。

## 0.1.0

- 独立比赛版的智能实验入口：规则故障诊断、可配置模型分析、实验计划草稿与报告导出。
- 保留 LabDeck / LabDock 的既有服务器管理、GPU 资源与实验任务能力，并隔离比赛版数据。
