# 离线演示操作（0.4.0）

打开 release/LabDeck Competition 0.4.0.exe，在“智能实验 → 演示入口”点击“载入预设演示计划”。无需服务器和 API 密钥。顶部控制条始终注明“模拟数据”，不会因演示操作调用 SSH 或模型。

## 成功路径，约三分钟

1. 任务栏自动打开预设的视觉训练任务。展开“命令与配置”，展示 batch size 32、代码目录与 Conda 环境。说明这份计划为预设配置。
2. 顶部点击“模拟首次显存不足”。查看第 1 次失败运行；点击“诊断第 1 次运行”，智能实验自动选中此任务与此运行。
3. 点击“收集证据并诊断”。展示规则结论、日志证据和 batch size 32 → 16 的命令对比。此处复用实际规则引擎，不调用模型。
4. 点击“审查并创建修复运行”，核对命令差异后“确认模拟排队”。可先点击取消，展示用户确认这一环节。
5. 点击报告“查看修复运行”，回到任务栏，高亮第 2 次运行；通过“查看修复验收”返回报告。
6. 顶部点击“模拟修复开始”，再点击“模拟验收成功”。展示模拟退出码 0 和验收通过；提醒这只展示进程验收，训练指标与产物质量未自动验收。
7. 在“闭环跟踪”查看记录，点击“打开修复运行”，说明原运行仍保留、参数变化可追溯。

## 失败路径，再加一分钟

点击“重置演示”重新开始。重复到模拟修复开始，选择“模拟再次失败”。原诊断的闭环显示模拟退出码 1，点击“查看新诊断”，展示第 2 次运行的新报告和 batch size 16 → 8。任务栏仍只有两次运行；第三次修复必须再次人工确认。

## 收尾

点击“退出演示”清除临时任务和报告，真实任务与真实诊断仍在。重置会换一组新的模拟编号，应用重开不恢复演示数据。模拟任务没有真实编辑、排队、删除、终端等入口；推进演示请使用顶部控制条。

## 展示真实模型与真实服务器

离线演示和模型能力分别验证。“模型设置”保存实际 API 配置并测试；在“实验任务”的真实任务中点击“基于此任务生成计划”，带入实际目录与环境，生成、审查、保存新草稿，再打开任务加入队列。

实际失败运行的诊断需点击“收集证据并诊断”，按需启用模型多轮检查。可执行修复目前只支持符合模板的 OOM batch 减半；确认后创建真实的新运行，应用自动跟踪并读取远程退出码，失败关联下一份诊断。参赛结果应使用真实模型与训练服务器取得日志和修复证据；离线模拟不能充当真实效果证明。

## 0.5.0 新增对照实验演示

进入「智能实验 → 对照实验 → 载入对照演示」。查看两个学习率和两个随机种子实际展开的四份配置，确认模拟入队，再选择「模拟正常结束（含指标变差）」或「模拟一项运行故障」。仓颉参数展开为真实执行；运行、退出码、指标和研究流程为临时模拟，不调用模型、不连接服务器、不写入真实研究历史。切换页面或退出会清除。完整说明见 RESEARCH-GUIDE.md。
