# 结构化实验结果采集

在「智能实验 → 对照实验」生成新批次前，可以填写「结构化指标文件」和「预期产物路径」。配置随该批方案保存，审查确认时展示，不会自动修改训练脚本。

## 配置路径

- 指标文件留空：继续采集日志末尾 240 行 / 64 KiB 中的最后匹配指标，并明确标为日志末值。
- 指定指标文件：读取该文件；缺失、无权限、格式错误时展示证据问题，不会把日志指标充当该文件结果。
- 预期产物：每行一项，最多 8 项。可以是文件或目录；只检查存在、类型、文件大小、修改时间和实际路径，不读取 checkpoint 内容，也不递归计算目录总大小。
- 路径支持远程绝对路径、相对本次运行代码目录的路径、`{runDir}` 和 `{runId}` 占位符。拒绝控制字符、父目录跳转和未知占位符。
- 推荐指标文件为 `{runDir}/metrics.json`，产物例如 `{runDir}/model.pt`。使用固定共享路径时提示覆盖风险。

调度器已经向训练进程导出 `LABDECK_RUN_ID`、`LABDECK_RUN_DIR`、`LABDECK_LOG_FILE`、`LABDECK_DATA_PATH` 和 `LABDECK_ARTIFACT_PATH`。训练脚本自行使用这些变量输出每次运行的结果；应用不会替脚本指定新的模型保存位置。

## 推荐的 metrics.json 协议

```json
{
  "schemaVersion": 1,
  "runId": "与 LABDECK_RUN_ID 相同的运行编号",
  "dataset": "vision-validation-v1",
  "epoch": 12,
  "metrics": [
    {
      "name": "accuracy",
      "value": 0.72,
      "split": "validation",
      "unit": "ratio",
      "direction": "maximize"
    },
    {
      "name": "loss",
      "value": 1.14,
      "split": "validation",
      "unit": "dimensionless",
      "direction": "minimize"
    }
  ]
}
```

`metrics` 支持数组、数字映射或带元信息的映射；也支持简单的 `{"accuracy":0.72,"loss":1.14}`。简单格式中没有声明的数据集、阶段、单位、epoch、step 和方向会显示为未知，不自动推断。

每份文件支持 1～40 个有限数值指标，文件上限为 128 KiB，UTF-8 编码。`schemaVersion` 如填写必须为 1。`direction` 如填写只能为 `minimize`、`maximize` 或 `observe`，不设达标阈值。指标名称支持字母开头及字母、数字、`_ . / % -`；字符串数值、NaN/Infinity、重复口径和未知协议字段会被拒绝。文件级元信息可以由单项指标覆盖。

下面是训练脚本末尾自行写入结果的例子，数值仅用于展示协议：

```python
import json
import os
from pathlib import Path

run_dir = Path(os.environ["LABDECK_RUN_DIR"])
result = {
    "schemaVersion": 1,
    "runId": os.environ["LABDECK_RUN_ID"],
    "dataset": "vision-validation-v1",
    "split": "validation",
    "epoch": 12,
    "metrics": {
        "accuracy": {"value": 0.72, "unit": "ratio", "direction": "maximize"},
        "loss": {"value": 1.14, "unit": "dimensionless", "direction": "minimize"}
    }
}
temporary = run_dir / "metrics.json.tmp"
temporary.write_text(json.dumps(result, ensure_ascii=False), encoding="utf-8")
os.replace(temporary, run_dir / "metrics.json")
```

## 如何理解结果

页面将三个维度分开：

1. **进程状态**：远程退出码与任务记录一致才显示已核对正常结束；非零退出码显示运行故障，缺少退出码或状态冲突显示待确认；取消运行不作科研比较。
2. **结果证据**：展示指标及指定产物是否已取得、是否属于本次运行。缺少指标、指定产物缺失或文件归属未核对时，显示部分证据或尚无结果证据。
3. **研究观察**：记录实际指标及口径。低 accuracy、高 loss 或假设未成立不等于运行故障，不自动触发修复。

同名指标如果来源、数据集、阶段、单位、epoch、step 或优化方向不同，会分列展示。元信息缺失时不能据此认定口径一致。规则分析只并列记录相同声明口径的值域，不做自动优劣判定或多 seed 统计。

文件中的 `runId` 若与当前运行不一致，指标不会被采用。没有 runId 的文件，位于本次独立运行目录时可以按目录关联；其他位置显示归属待核对。修改时间早于运行开始时间时提示可能是旧文件或服务器时钟偏差，不作为已核对归属的结果。文件自报 runId 和目录关联并非密码学溯源，仍需正确配置训练脚本。

## 补齐证据与导出

本批结束后，点击「重新采集结果」重新读取日志、退出码、指标文件和产物元信息。此操作不创建任务、不启动新运行、不自动修复，也不调用模型；结果先更新为规则观察。需要模型重新解释时，再使用「补充分析」，沿用每批最多两次的预算。

JSON 导出包含采集配置、指标元信息、来源路径、文件状态、采集时间、进程和证据状态以及研究时间线。不会导出 checkpoint 内容或原始指标文件中的未知字段。旧版检查点没有采集配置时继续使用日志模式，旧记录仍可查看和重新采集。

## 实现与测试边界

文件读取是固定只读 Python 程序，通过 SSH 调用系统 `python3` 或 `python`，需要 Python 3；路径作为 JSON 数据参数传入。指标只读取普通文件，拒绝直接符号链接和特殊文件；使用有限读取并核对读取期间的变化。祖先目录的符号链接可能影响实际路径，页面展示解析后的路径及运行归属。产物只做元信息检查。

源代码入口：`src/shared/research-results.ts`、`src/main/result-collector.ts`、`src/main/research-service.ts` 和 `src/renderer/src/components/ResearchResults.tsx`。本地 Python 可用时，采集器测试会执行实际只读程序；没有本地 Python 时这一个可选测试跳过，其他协议与 SSH 夹具测试仍可执行。

已有自建实验执行 Harness 提供输入校验、人工确认、工具与执行预算、去重、检查点恢复及证据边界；LangGraph 编排节点。当前没有专门的真实模型评测 Harness，不包含故障案例集上的诊断准确率、工具选择质量或模型成本对比。

## 从实验任务池进入智能实验

智能实验的主入口为“仓库启动、对照实验、故障诊断”。模型设置可从应用设置或智能实验的“更多”进入，演示模式也收在“更多”。

- 任务池点击“AI 阅读实验仓库”，或在任务详情点击“分析仓库启动方式”，从仓库依据开始准备第一次实验。
- 有明确启动配置并完成核对后，可保存为新的任务草稿；确认入队仍在任务池进行。需要快速按明确需求生成草稿时，可从“仓库启动”右上方进入“快捷计划”；返回仓库分析会保留当前方案。
- 来源任务和参数变体详情中的“智能实验记录”展示所属批次、准确运行编号、采集结果与分析，可互相跳转。
- “设计对照实验”提前提示命令兼容性。当前参数展开仅支持简单的 `python xxx.py` 命令；bash、torchrun、accelerate、模块入口仍可作为普通任务运行，但不直接进行参数展开。AI 范围建议只使用原命令中已出现的带值参数，不填充默认学习率或随机种子。
- 失败运行的诊断和重试状态均保留在对应任务/报告中，不再设独立“闭环跟踪”页面。“正常退出”只描述进程状态，不表示科学指标达标。

## 模型调用与重试预算

- 启用模型诊断时默认“快速分析”，只调用一次模型并汇总已有证据。用户可手动选择深入检查，最多四轮模型请求、四项只读检查。
- 确认重试时，“再次失败调用模型快速分析”默认关闭。关闭时失败后仍生成规则诊断；开启后最多进行一次模型快速分析。状态轮询不调用模型，后续运行仍需再次确认。
- 已存在的重试记录保留原有模型跟踪偏好；暂停跟踪可停止后续后台核对。
- 对照批次中的故障自动关联规则诊断，不因勾选结果分析而额外发起模型诊断；进一步分析可从具体运行手动发起。
- 仓库启动分析最多请求四次模型（侦察最多三次、方案生成一次），不自动重试；侦察中断时保留已读内容，方案生成失败后等待手动重试；继续已有 LangGraph 流程、确认步骤、补充信息后复检、同步任务状态均不请求模型。输出被模型服务截断时明确报错，不自动重新请求。

## 仓库启动助手：第一次实验如何启动

打开“智能实验”先显示“启动新实验”和“诊断已有实验”两个入口，最近失败运行和历史诊断也可直接继续。选择“启动新实验”进入仓库启动助手。这项功能适用于已经从 GitHub 克隆到服务器的实验仓库，不需要先有失败运行。

1. 选择仓库所在的实际服务器与 SSH 连接路径，填写服务器上的仓库根目录；也可以点击“扫描”在常见目录中查找带 `.git` 或 README 的候选，点击“浏览”从主目录逐级选择，或从输入框的最近路径候选中选择。主机指纹需先在资源页面确认。
2. 填写本次目标，例如“用已有数据跑通一次训练”或“只运行作者的评估流程”，点击“分析启动方式”。系统先读取文件清单与说明/依赖/入口，模型再按需只读侦察引用的脚本和配置，最后生成一次启动方案（总读取约 30 万字符）。
3. 默认选中仓库内全部可读文本文件；模型优先读取 README、依赖与入口，并可按需读取引用的脚本、配置或目录清单。侦察和引用补读均限制在勾选范围内，未勾选的文件不会被读取或发送；读取清单本身不调用模型。
4. 查看启动指南。AI 按顺序解释环境/依赖、数据/权重准备、训练/评估和输出，列出需要手动运行的命令、文件依据和待确认项。每个步骤明确工作目录、环境以及“文档原命令/AI 建议”分类；引用行号对应的原文由程序提取，模型声称的文档命令未匹配原文时会降为建议。界面可以展开实际阅读的编号文件内容。
5. 启动配置核对完成并确认准备事项后，可将单条 Python、bash 脚本、torchrun 或 accelerate launch 命令保存；应用会直接打开 GPU 选择窗口，确认后加入队列。指南中的安装、下载等准备命令不会自动执行。准备事项可逐项勾选，也可在确认已完成后一键全部确认或撤销；这仍是用户确认，不代表平台已执行或验证。若有明确的受支持启动命令、但仍存在非阻塞的待确认信息，可选择“仍然保存为草稿”，待确认项会写入任务备注，启动前仍需在任务池核对。

README 或配置文件中引用的脚本会优先补充到同一轮读取；入口可定位时模型会给出最小 suggested 启动命令，程序也会在模型留空时从 README 原文回退一条受支持的命令。`environment.yml` 的 `name` 与命令中的 `--data` 等参数会用于预填环境名和数据目录；服务器上的 Conda 环境会作为候选并与输入值比对，仓库内 `data/`、`datasets/`、`checkpoints/`、`weights/` 等目录也会预填或提示。数据目录会做一次只读存在性核对，结果显示为警告；预填的数据目录和环境名会自动回答对应的模型问题，不再要求重复填写，以上均可在右侧修改。只有明确询问目录或环境名称的问题才自动回答，数据预处理、划分、依赖或 CUDA 版本等要求仍需实际核对。

仓库读取与实验执行使用同一台服务器和 SSH 连接路径。分析结果会将仓库根目录及相对启动子目录填入任务启动目录，保存前仍需人工核对。

读取范围为仓库内可读文本文件，单次分析总读取约 30 万字符（可用环境变量 `LABDECK_REPO_MAX_CHARS` 调整）。模型先读 README、依赖与入口，再按需调用只读工具（`read_file`、`list_dir`、`find_files`）读取引用的脚本、其 source 或引用的配置以及目录清单；每次读取都受总字符预算限制，超出时工具返回错误并在结果中标注。远超剩余额度的单个大文件不会读取，刚好超出的文件只保留开头并标为“部分内容”。不递归读取隐藏目录、常见数据/产物目录或软链接目录，不读取 `.env` 等隐藏文件和明显命名为凭据的文件，只处理 README、文档、Python/shell 脚本、依赖与环境配置等文本类型。引用只接受实际读取的文件行号。30 万字符是单次请求的实用上限，不是模型服务质量保证；仓库更大时请选择更具体的子目录。自动脱敏不能替代对发送内容的人工检查。

仓库侦察使用只读工具循环：在勾选范围内默认先读 4 个种子文件（README、依赖、入口等），之后最多 3 轮、8 次工具调用，模型可选择 `read_file`、`list_dir` 或 `find_files`；工具失败时自行调整。侦察完成后用同一份已读内容生成启动方案；侦察返回格式无效或请求失败时，保留已读内容和失败原因，再生成一次方案；生成失败不自动重试，也不重新扫描仓库。分析过程中界面会显示最近读取的文件/目录和当前阶段，仓库路径输入框会提供最近使用过的路径候选。

启动指南会只读核对模型建议的仓库内启动目录与实际入口文件。入口、关键路径或依据不足时标为“需要补充信息”。在流程右侧补充命令/目录和待确认问题的答复，再点击“检查并保存配置”，无需重新请求模型；答复记录为用户提供的信息，原文与系统核对分别保留。模块入口等无法定位仓库文件的情况也保持待确认。路径存在不表示依赖、数据、GPU 或科学效果已验证。编辑配置后，旧核对结果仅适用于原建议。启动指南是基于所读文件的建议，不是实机运行验证。资料不足时启动命令可为空，不能据此认定仓库能够直接运行。保存任务时，指南、来源文件和待确认项写入任务备注（最多 8000 字符）。


## 接手已经运行过的实验

智能实验允许从已有实验的任意阶段进入，不要求重新阅读仓库或先重跑一次：

- **任务池已有运行**：从首页最近失败运行、任务详情或运行历史进入诊断，准确定位该次运行；任务下拉选择默认优先失败运行，并要求明确选择运行编号。查看已有报告不会重新调用模型。
- **服务器手动运行的实验**：选择“指定服务器日志”，填写实际服务器、SSH 连接路径、现有日志的绝对路径；原命令、代码/工作目录和 Conda 环境可补充用于诊断。通过 SFTP 在文件开头/末尾最多扫描 256 KiB，优先选取 traceback、错误上下文和末尾状态，输出最多 240 行 / 64 KiB；片段省略处不会被表示为连续日志。不执行原命令。环境与命令是用户提供的上下文，进程状态保持未核验；日志可能混有多次运行或仍在写入，不能据此伪造任务池里的失败运行。
- **只有错误文本**：选择“粘贴错误日志”，仅根据文本给出分析，不能自动检查服务器或执行修复。

手动实验诊断与现有规则、快速单次模型分析、深入只读检查和历史报告共用流程。深入检查仅使用已提供的服务器/目录/环境，项目文件和日志始终作为不可信证据，不执行其中的指令。

需要继续运行时，在诊断报告的“接入任务池继续实验”中审核代码目录、启动命令、Conda 环境和数据目录，可手动带入受支持的 batch size 调整建议。保存只创建 `planned` 草稿，原日志保留、原运行不会回填为虚构记录；到任务池确认入队后才产生新的实际运行。重复保存同份诊断会返回已关联的任务，避免意外创建多个草稿。新任务备注保留诊断 ID、原日志位置与来源限制。


## 仓库启动的 LangGraph 步骤与恢复

仓库启动已复用项目已有的 LangGraph，使用磁盘检查点保存真实流程状态：

1. `read_and_analyze`：只在新建流程或用户明确重试未完成的分析节点时，读取所选仓库文件、最多三次模型侦察加一次方案生成，并生成路径核对结果。
2. `assess`：结合缺失信息、用户的准备确认和任务池真实状态，计算下一步。
3. `await_action`：暂停等待用户操作，不自动安装环境、下载数据、执行命令或发起后续模型请求。
4. `apply_action`：处理补充复检、步骤确认、创建草稿和同步任务状态，再回到评估与等待。

每项准备步骤显示命令、工作目录、环境及原文依据。准备/结果查看步骤可由用户确认，明确标为“用户确认，不代表系统验证”；训练启动步骤不能勾选成成功，状态来自任务池实际运行。创建草稿前需要确认准备步骤，实际入队仍在任务池单独审核。

补充复检会保存用户提供的配置和答复，只读重查仓库内启动目录与入口文件；字段修改后先复检，再重新确认准备步骤。创建任务后到任务池编辑实际配置，避免流程快照与已提交任务混淆。流程绑定第一次实际运行；后续独立运行成功不会覆盖先前的失败记录，指定运行删除后显示缺失。

在“已保存的分析”中可恢复指南、补充答复、步骤确认与关联任务；重启应用不会自动重试未完成的付费分析。中断的分析节点需要明确点击重试，界面提示可能再次调用模型。流程检查点保存在参赛版独立用户数据目录的 `repository-workflows/` 下，最多记录 100 个流程。

## 日志取证、诊断复用与模型用量

- 读取范围有固定预算：文件较小时最多检查 256 KiB；较大文件检查开头 192 KiB 和末尾 64 KiB，中间区域不扫描。优先提取早期 traceback/明确错误及上下文，保留末尾状态，结果最多 240 行 / 64 KiB。行号相对于报告片段，不能当成完整文件行号。
- 用户再次诊断时，先重新读取有限证据。实际运行与服务器日志在已选日志、来源上下文、运行记录、诊断模式、模型配置与提示词版本相同时，可在 24 小时内复用已完成报告；示例日志与粘贴日志每次重新生成，不参与复用。取消、未完成的模型分析不作为已完成的模型结果复用。
- 复用不会再次调用模型，报告保留原分析时间；深入检查中的 GPU/环境信息仍是原采集时刻，需要更新时勾选“强制重新分析”。规则诊断的新资源/环境证据若发生实质变化也会使复用失效。
- 每份分析展示模型请求数及服务返回的输入、输出、总 token 数。服务没有返回或记录缺失时显示“未知”，不伪装为 0；复用时明确显示本次新增请求 0 次，并另列原分析用量。这是单份分析的服务统计，不等于账号账单或费用估算。


## 结构化模型输出与截断处理

普通结构化请求的输出上限为 4096 tokens；仓库分析不设置本机输出上限，由所配置模型服务决定生成长度，超时为 600 秒，普通结构化请求为 90 秒。官方 DeepSeek 地址上的 Flash/Pro 结构化请求显式关闭默认思考并使用 JSON 模式；其他兼容服务不发送 DeepSeek 专属参数。

截断结果或空的最终回答不会被保存为有效方案，也不自动发起新的付费请求。错误会保留仓库、目标和文件选择；用户可明确重试分析节点或调整阅读范围。后续补充信息、路径检查、准备确认和同步任务状态不调用模型。补充环境或数据而未修改命令时，保留原启动命令的文档引用；修正目录/入口后直接复检，不要求为机器生成的路径错误另填文字答复。


引用按实际读取的文件行号核对，允许较长的连续原文和连续阅读窗口间的引用，不以“超过 8 行”判为无效。引用范围内每一行都必须已读；跨越省略区间、未读行或未知文件时仍拒绝。引用原文由程序提取，界面可展开滚动查看，不依赖模型提供的引用文本。

取消勾选的文件不进入模型的文件清单，也不能被补读工具读取。分析期间可以点击“取消分析”，中止模型请求并关闭当前读取会话；取消不创建任务或运行。已完成的补充、路径复检和状态同步均不请求模型。README 回退只采用与训练/评估目标匹配的唯一候选，安装/预处理命令不会被当作实验启动，多条候选保持待人工选择。
