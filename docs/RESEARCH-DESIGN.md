# 实验研究流程与界面设计

## 职责

- LangGraph / Node 主进程：expand → review interrupt → queue → observe interrupt → collect → diagnose（有故障时）→ analyze。
- 仓颉 CLI：参数去重、配置组合、预算与命令展开。主进程通过受控协议调用，并核对输出。
- 实验 Harness：输入/模型结构校验、只读证据采集、诊断工具限制、次数预算、确认、去重、恢复和回放。
- 原有调度器：GPU 资源检查、SSH 执行、远程状态跟踪。研究流程不重复维护第二套任务状态。
- 大模型：建议参数范围、解释观察、提出下一步。执行故障和科学结果分支依据任务记录及证据，指标下降不进入自动修复。

检查点保存节点状态，实际任务存储保存任务与运行。入队效果以研究编号 / 配置序号标记去重，避免 interrupt 重新执行或部分失败时重复启动。索引写入中断后可从已存在的检查点恢复记录。

## 视觉方案

沿用现有工作台主题及字体，主色槽为 bg #07101d、panel #0c1929、text #e8f0f8、muted #8496a9、teal #5ed6c8、amber #e9bb65；另一主题仍使用现有对应变量。字体沿用工作台的 Inter / Segoe UI / Microsoft YaHei UI，命令采用 Cascadia Code / Consolas。避免新增装饰图、渐变或卡片大数字。

左侧是新批次方案及历史选择；右侧是选定的已保存方案、配置差异表、运行证据、分析和时间线。流程节点有真实先后顺序，只有当前位置与已执行节点改变状态。按钮使用「生成待审查方案」「确认本批加入队列」「检查进度」「载入下一批建议」，不把 LangGraph 或 Harness 术语放进操作按钮。

离线演示保留一条 amber 提示，准确区分实际参数展开与模拟运行。模拟确认不走真实入队接口；模拟数据不进入持久化。真实配置与临时模拟均在同一配置表布局展示，减少演示与实际使用的差异。

## 界面复核

真实 Electron 流程验证已检查深浅主题、1280×840 布局和整页横向溢出。配置表在自身容器滚动，命令换行，键盘 focus 沿用工作台样式。截图保存在 `docs/screenshots/research-*.png`。左侧用于设计新批次，右侧展示历史快照，输入修改不会更改已保存方案。
